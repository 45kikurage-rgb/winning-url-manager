当選URL管理・共有送信版

このZIPは、一時箱・全ファイル重複確認・コピー制限に対応しています。
必ず winning-url-api を先にデプロイしてから更新してください。

GitHub の winning-url-manager を main ブランチへ反映します。画面配置機能の主な対象:
- index.html
- share.html
- home-layout.html
- home-layout-edit.html
- home-layout-marker-core.js
- home-layout-read.html
- home-layout-admin.html
- manifest.webmanifest
- sw.js
- icon-any.png
- icon-maskable.png

Cloudflare は GitHub 更新後に自動デプロイされます。

Android:
1. Chromeで https://winning-url-manager.45kikurage.workers.dev を開く
2. 既存のホーム画面ショートカット/PWAがある場合は一度削除
3. Chromeメニューから「アプリをインストール」または「ホーム画面に追加」
4. 対象ページで「共有」
5. 共有先に「URL送信」または「当選URL管理」が表示されたら選択
6. share.html が起動し、自動的に現在選択中の保存先へ送信

ホーム画面更新:
1. 画面下部の「画面配置」を押す
2. 抽選後の.novabackupを貼り付ける
3. 「解析と端末用ファイル作成へ」を開き、バックアップを解析する
4. 自動判別された端末、キャンペーン別の残り・今回当選・既存当選件数を確認する
5. 端末用ファイルを作成して履歴を確定し、保存する
6. NOVAで復元した後、「サイト作業を完了」を押す

新しいキャンペーンの追加:
1. 配置管理の「キャンペーン」を開く
2. キャンペーン名を入力して「追加」を押す
3. ↑↓で一覧を並べる（上から追加ページの配置順）
4. 各端末の最新NOVAバックアップを通常どおり解析してファイルを作る
5. 新規キャンペーンは全LINEを30件／ページで自動配置し、その時点のLINE総数を固定する

安全条件:
- 5ページへの新規配置は端末の固定初期データが121～150LINEの場合だけ実行する
- 新規キャンペーンに当落履歴がある場合は自動配置を停止する
- 1～6段目のLINEを、未抽選・ハズレを区別せず「残り」として扱う
- 7段目は、直接配置したLINEもフォルダ内LINEも今回当選とし、過去の当選履歴は配置外でも維持する
- 当選履歴のないLINEが追加ページから消えている場合は、誤削除防止のため処理を停止する
- 作成後にキャンペーン順、全LINEの並び、7段目の残存、NOVAデータ整合性を再検査する
- 当落修正はキャンペーン、端末、LINEを個別に選び、現在値と変更後を確認してから確定する

端末ごとの初期データは事前登録済みです。1～5ページまたはLINEアカウントを変更した時だけ、
日常作業画面下部の「初期データ・管理」から更新します。

端末06は専用データとして保存します。アプリIDは初期データ内の実在値だけを使い、
初期データに存在しないアプリIDは追加ページへ配置しません。
1～6段目は初期データのLINE配置へ戻し、最下部のドックは抽選後データの状態を維持します。
キャンペーンごとの当落と配置順はサーバーへ保存します。追加ページの1～6段目を残り、7段目は直接配置・フォルダ内のどちらも当選として読み、
残りLINEを管理画面のキャンペーン順に初期配置の優先順で5×6配置します。統計は当選数／キャンペーン開始時LINE総数です。
作成ファイル名は「MMDD_HHmm_端末XX_キャンペーン名_編集済.novabackup」です。通常作業ではZIPを作成しません。
旧NOVA配置照合・CSV・AI確認用JSON作成機能は削除済みです。

新規URLは一時箱へ受付されます。
管理画面の「全ファイル重複チェック」または毎日6:30・22:00の自動確認後、
ユニークURLだけが継続箱、収益、コピー対象へ反映されます。
